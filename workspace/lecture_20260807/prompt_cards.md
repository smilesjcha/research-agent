# 연구 환경 전환 요청문 카드

## 가장 먼저 써볼 한 가지 부탁

```text
이 자료들을 읽고,
확인된 사실·아직 확인할 내용·다음 행동을 1쪽으로 정리해 주세요.
원문 근거를 붙이고, 추정하지 말고, 제가 검토할 부분은 따로 표시해 주세요.
```

첫 결과를 본 뒤에는 아래처럼 한 가지만 더 부탁한다.

```text
- 결론과 다음 행동이 먼저 보이도록 더 짧게 고쳐 주세요.
- 사실·해석·확인 필요를 서로 다른 칸으로 나눠 주세요.
- 틀렸거나 빠졌을 가능성이 큰 부분 세 곳을 먼저 찾아 주세요.
```

## 0. 원하는 연구지원 서비스 발견

```text
나는 [사용자]가 매주 겪는 [반복 문제]를 줄이고 싶다.
현재 입력은 [파일·메일·시스템·회의]에 흩어져 있다.
한 화면에서 [보고 싶은 정보와 행동]을 보고 싶다.

사람 승인점: [누가 무엇을 확인하고 승인하는가]
사용하지 않을 데이터: [개인·건강·IRB·저작권 민감자료]
1주 완료 기준: 샘플 데이터로 화면을 만들고 사용자 5명이 오류·누락을 표시한다.
```

## 0-A. 온라인학습 운영 브리프

```text
온라인학습지원센터의 이번 주 운영 현황을 한눈에 보고 싶다.
과정별 집계, 콘텐츠 문의 유형, 교사 지원 요청, 지난주 대비 변화를 보여준다.
개인을 자동 평가하지 않고, 확인이 필요한 항목과 그 이유를 따로 표시한다.
담당자가 원자료를 대조하고 ‘공유 승인’하기 전에는 외부 배포하지 않는다.
```

## 0-B. 온라인 콘텐츠 품질 점검

```text
온라인 학습 콘텐츠 시안을 교육과정 정합성, 접근성, 활동 다양성, 형성평가 문항 관점에서 점검한다.
각 제안은 문제 위치, 적용 기준, 수정안, 사람의 수락·보류·반려 상태를 포함한다.
교과·접근성 전문가의 결정을 대신하지 않고 수정 근거와 버전을 남긴다.
```

## 0-C. 학습지원 신호 탐색

```text
비식별 가상 학습기록 CSV에서 참여 감소·미제출 추세를 보여준다.
결과는 ‘지원 여부 결정’이 아니라 연구자가 검토할 후보와 추가 질문으로만 출력한다.
건강·장애·가정환경 등 민감정보를 입력하지 않고 자동 조치나 불이익을 금지한다.
```

## 0-D. 연구 근거 지도

```text
정책 요약문의 각 주장마다 출처, 페이지·절, 지지 수준, 확인 상태를 연결한다.
원문을 읽지 않았으면 ‘초록만 확인’, 위치가 없으면 ‘추가 확인’으로 남긴다.
AI는 핵심 인용을 확정하지 않고 인용 없음·약한 지지·과장 후보만 표시한다.
```

## 0-E. 학생지원 MVP 1쪽 PRD

```text
KEDI 공개 사업과 현재 서비스를 먼저 확인하고, 공개적으로 확인되지 않는 기능은 ‘강의 제안’으로 구분한다.

대상: 온라인 보충과정 등 비민감 온라인 학습 맥락의 학생.
문제 가설: 이번 주 할 일과 도움 요청 경로가 흩어져 다음 행동을 정하기 어렵다.
해결 가설: 목표, 작은 활동, 다음 한 걸음, 사람 도움 요청, 회고를 한 화면에 연결한다.

출력:
1. 문제와 근거 상태
2. 사용자가 해결하려는 일
3. 반드시 필요한 기능과 이후 기능
4. 자동 채점·위험 예측·진단을 포함한 비범위
5. 중심·결과·품질·안전 지표의 정의
6. 가상 자료 → 내부 검토 → 승인된 작은 현장 실험
7. 확대·수정·축소·중단 조건

제약: 실제 학생 식별·건강·상담정보를 입력하지 않는다. 학생을 자동 평가하거나 지원 자격을 결정하지 않는다.
```

## 1. 부탁을 더 구체화하는 네 가지

```text
원하는 결과
- 이번 작업에서 만들거나 바꿀 결과는 무엇인가?

참고할 자료
- 먼저 읽을 파일, 데이터, 예시, 현재 단계는 무엇인가?

조심할 것
- 출처, 기간, 개인정보, 연구윤리, 쓰기 권한, 금지 사항은 무엇인가?

원하는 모양과 확인 방법
- 어떤 파일이 생기고, 어떤 검증을 통과해야 완료인가?
```

## 2. 연구질문 범위화

```text
workspace/00_project_brief.md와 workspace/01_research_question.md를 먼저 읽어라.

목표: 교육공학 연구질문을 문헌 검색이 가능한 수준으로 좁힌다.
제약: 대상, 개입, 결과, 맥락 중 확인되지 않은 요소를 임의로 채우지 않는다.
출력: 질문 후보 5개, 영어 검색어, 범위 위험, 실행 가능성, 선택 기준.
완료 기준: 각 후보가 서로 다른 범위 선택을 보여주고, 다음 검색 단계의 입력으로 저장 가능하다.
```

## 3. 문헌 후보 검색 점검

```text
notebooks/01_search_papers.ipynb와 data/search_strategy.md를 읽어라.

목표: 현재 OpenAlex 검색의 재현성과 노이즈 위험을 점검한다.
제약: 검색 결과를 핵심 근거로 확정하지 말고 후보로만 취급한다.
출력: 검색식 진단, 추가 검색식 3개, 누락 위험, 노이즈 패턴, 수정 제안.
검증: 검색식, 검색 필드, 언어, 연도 범위, 실행일, 결과 수가 모두 추적 가능해야 한다.
```

## 4. 원문 근거 추출

```text
선택한 PDF와 references/notes/paper_note_template.md를 읽어라.

목표: 내 원고에서 사용할 수 있는 주장별 근거를 추출한다.
반드시 포함: 연구질문, 방법, 자료·참여자, 핵심 결과, 한계, 페이지·절, 짧은 발췌 또는 정확한 요약.
제약: 초록만으로 핵심 인용을 확정하지 않는다. 위치를 확인하지 못하면 ‘추가 확인’으로 남긴다.
완료 기준: 주장 → 출처 → 페이지·절 → 지지 수준 → 확인 상태가 한 행으로 연결된다.
```

## 5. 비판적 자기검토

```text
초안을 지지하려 하지 말고 거절 사유를 먼저 찾아라.

검사:
- 인용이 없는 사실 주장
- 출처보다 강한 과장
- 관련은 있지만 직접 지지하지 않는 약한 인용
- 초록만 확인한 문장을 원문 확인처럼 쓴 경우
- 서로 다른 집단·맥락·결과를 합친 문장

출력: 주장 번호, 위험 유형, 근거, 수정안, 사람의 확인이 필요한 지점.
```

## 6. 도구 사용·쓰기 경계

```text
읽기 작업은 자율 수행한다.
새 산출물은 workspace/ 또는 references/ 아래에만 만든다.
원본 데이터와 기존 노트북은 덮어쓰지 않는다.
외부 전송, 공유, 삭제, 권한 변경, 개인정보 포함 작업은 실행 전에 사람의 승인을 받는다.
완료 시 변경 파일, 실행한 검증, 남은 추가 확인 항목을 보고한다.
```

## 7. 30일 현장 실험 설계

```text
반복 빈도가 높고 위험도가 낮은 연구 업무 하나를 선택한다.

출력:
1. 입력과 출력
2. 사람이 승인할 지점
3. 실패 사례 5개
4. 자동 검증 3개
5. GitHub에 남길 로그
6. 30일 성공 지표

제약: 개인정보·연구윤리 심의·최종 정책 판단은 자동화 범위에서 제외한다.
```

## 8. Codex에 내 컴퓨터용 시안 요청

```text
위 서비스 요청문을 읽고 workspace/ 아래에 교육용 웹 시안을 만들어라.
비전공 연구자가 평소 말로 입력하고 결과를 눈으로 확인할 수 있어야 한다.

기본 상태에서는 네트워크 없이 가상 자료만 사용한다.
AI 연결용 비밀 키는 브라우저에 넣지 말고 서버 환경변수에서만 읽는다.
개인정보·건강정보·연구윤리 심의 대상 자료의 입력 경고와 사람 승인점을 화면에 고정한다.
완료 전에 모바일·데스크톱 화면, 빈 입력, 비밀 키 없음, 민감자료 입력 거절을 검증한다.
Vercel 배포 파일과 README를 함께 만든다.
```

## 9. 기능 제안의 PRD 연결 점검

```text
현재 기능 목록을 검토하라. 기능마다 다음을 한 행으로 연결한다.

- 해결하려는 사용자 문제
- 기대하는 행동 변화
- 연결되는 결과·품질·안전 지표
- 필요한 데이터와 최소 수집 범위
- 사람이 승인할 지점
- 실패 시 중단·복구 방법

연결되는 문제나 지표가 없는 기능은 ‘이후 검토’로 이동하거나 삭제 후보로 표시한다.
출력: 반드시 필요 / 이후 검토 / 삭제 후보와 판단 이유.
```
