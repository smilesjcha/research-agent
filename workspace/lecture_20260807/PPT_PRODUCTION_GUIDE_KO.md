# KEDI 강의 PPT 제작 지침

## 1. 문서 목적

이 문서는 한국교육개발원 디지털교육연구실 대상 강의 자료를 일관된 품질로 수정·확장하기 위한 제작 기준이다. 장표의 표현, 정보 구조, 시각 체계, 실제 시연, 출처 표기, 최종 검수 기준을 함께 정의한다.

적용 대상은 다음과 같다.

- 본 강의 PPT와 후속 강의 자료
- 연구 환경 자동화 사례 장표
- Research-agent·Jupyter·GitHub 실제 시연 장표
- 내 컴퓨터의 시안과 Vercel 웹 공유 장표
- 참가자용 요청문 카드와 실습 자료

이 문서의 최우선 기준은 “AI를 잘 설명하는 자료”가 아니라 “연구자가 자신의 업무를 새롭게 볼 수 있게 하는 자료”이다.

주요 청중은 디지털교육 연구사업을 기획·수행·평가하고, 보고서·데이터·서비스 산출물의 품질과 책임을 담당하는 박사급 연구원이다. 연구 전문성을 전제로 하되 Codex·GitHub·배포 환경처럼 익숙하지 않을 수 있는 도구만 필요한 수준에서 설명한다.

## 2. 커뮤니케이션 목표

강의가 끝났을 때 참가자는 다음 세 가지를 이해해야 한다.

1. 가장 좋은 첫 활용은 자료를 읽어 `확인된 내용·확인할 내용·다음 행동`을 1쪽으로 정리하게 하는 일이다.
2. 좋은 답 한 번보다 자료·작업 순서·품질 기준·사람 확인·변경 기록이 이어지는 연구 환경이 중요하다.
3. AI는 후보 탐색·초안·분류·점검을 지원하지만 연구 판단, 학생 지원, 대외 공유의 최종 책임은 사람에게 남는다.

강의 전체를 회수하는 Agentic AI 핵심 철학은 다음과 같다.

> 인간이 방향을 제시하고, 에이전트가 실행하며, 다음 판단은 근거에 둔다.

영문 표현을 함께 사용할 때는 `Humans steer · Agents execute · Evidence decides`로 병기한다. 다만 `Evidence decides`를 결정권의 자동화로 설명하지 않는다. 최종 책임은 사람에게 남기고, 사람의 판단 기준을 직관보다 로그·실험 결과·평가 지표에 둔다는 뜻으로 해석한다.

장표는 이 세 가지 결론을 향해 누적적으로 전개한다. 개별 장표가 흥미롭더라도 전체 결론과 연결되지 않으면 삭제하거나 발표자 노트로 이동한다.

## 3. 전체 제작 원칙

### 3.1 한 장표, 한 가지 역할

한 장표에는 하나의 질문 또는 하나의 결론만 둔다. 한 화면에서 정의·사례·절차·위험·실행안을 모두 설명하지 않는다.

- 정의 장표: 개념과 구성 요소
- 비교 장표: 두 대상의 차이
- 근거 장표: 자료가 의미하는 바
- 시연 장표: 화면에서 볼 지점
- 실행 장표: 다음 행동과 완료 기준

### 3.2 제목이 먼저 결론을 전달

본문을 읽기 전에 제목만으로 장표의 역할을 알 수 있어야 한다. 다만 모든 제목을 `~합니다`로 끝내는 보고서 문장으로 만들지 않는다.

기본 제목은 다음 네 유형을 사용한다.

| 유형 | 구조 | 예시 |
|---|---|---|
| 핵심 개념형 | 대상 + 핵심 개념 | `AI 연구 환경의 여섯 요소` |
| 판단 기준형 | 대상 + 기준·조건·원칙 | `핵심 문헌 확정의 조건: 점수가 아닌 원문` |
| 관계·비교형 | A와 B의 차이·연결·구분 | `관련성·품질·인용 가능성의 구분` |
| 전환·실행형 | 기존 상태에서 바뀌는 방향 | `업무 단위의 전환: 문서에서 작업 흐름과 주장으로` |

질문형이나 동사형 제목은 다음 경우에만 제한적으로 사용한다.

- 청중에게 실제 답을 요구하는 진단 장표
- 실습 시작을 알리는 행동 지시
- 발표자가 말로 강하게 회수해야 하는 결론 장표

### 3.3 명사형 제목의 사용 기준

명사형은 문장을 기계적으로 자르는 방식이 아니라 핵심 판단을 압축하는 방식으로 사용한다.

좋은 예:

- `AI 중심 업무의 조건: 재실행·확인·복구`
- `읽기 범위와 쓰기 범위의 분리`
- `영향도·복구 가능성에 따른 승인 시점`

피해야 할 예:

- `AI 활용을 통한 업무 환경의 혁신적 개선 추진`
- `연구지원체계 고도화 기반 마련을 위한 방향성 제시`
- `디지털교육연구실 업무에의 AI 적용 가능성 검토`

명사만 여러 개 이어 붙인 행정 문구는 가독성을 낮춘다. 제목에는 핵심 명사 두세 개와 관계를 보여주는 조사·부사만 남긴다.

### 3.4 제목 길이와 문장 부호

- 한 줄 제목은 한글 기준 약 18–30자를 권장한다.
- 34자를 넘으면 핵심어를 줄이거나 두 줄형 장표로 전환한다.
- 구분 장표는 최대 두 줄, 일반 장표는 한 줄을 우선한다.
- 콜론은 앞에 개념, 뒤에 판단이나 구체 항목이 올 때만 사용한다.
- 화살표는 순서나 변화가 실제로 있을 때만 사용한다.
- 제목 끝에 마침표를 사용하지 않는다.
- 따옴표는 실제 질문·요청문·발화에만 사용한다.

## 4. 제목 수정 기준과 적용 예시

| 기존 문장형 | 수정한 핵심 메시지형 | 수정 이유 |
|---|---|---|
| AI 중심 업무는 다시 실행하고 확인할 수 있어야 합니다 | AI 중심 업무의 조건: 재실행·확인·복구 | 조건을 세 단어로 압축 |
| 문서 중심에서 작업 흐름과 주장 단위로 이동합니다 | 업무 단위의 전환: 문서에서 작업 흐름과 주장으로 | 변화의 대상과 방향을 분리 |
| 연구 환경의 신뢰도는 세 요소의 곱입니다 | 연구 환경 신뢰도의 세 요소 | 본문 수식과 제목 역할 분리 |
| AI에 맡기는 범위는 단계적으로 넓혀야 합니다 | AI 위임 범위의 단계적 확대 | 당위 표현을 운영 원칙으로 전환 |
| AI가 읽을 범위와 쓸 범위를 나눕니다 | 읽기 범위와 쓰기 범위의 분리 | 핵심 비교만 유지 |
| 품질 점수는 읽을 순서를 정하는 참고 기준입니다 | 품질 점수의 역할: 읽기 우선순위 | 점수의 용도를 명확히 표현 |
| 핵심 문헌은 점수만으로 확정하지 않습니다 | 핵심 문헌 확정의 조건: 점수가 아닌 원문 | 부정문을 판단 기준으로 전환 |
| 실행 전 여섯 가지를 확인하면 사고 범위가 줄어듭니다 | 실행 전 여섯 가지 확인 사항 | 결과 설명은 본문으로 이동 |

## 5. 한국어 표현 원칙

### 5.1 두괄식 본문

본문도 첫 문장에서 의미를 먼저 전달한다.

- 첫 문장: 결론 또는 적용 원칙
- 둘째 문장: 이유나 근거
- 셋째 문장: KEDI 업무 예시 또는 주의점

나쁜 순서:

> 최근 생성형 AI가 발전하고 있으며 여러 기관에서도 활용이 확대되고 있습니다. 이에 따라 다양한 가능성이 존재합니다. 따라서 연구 환경을 검토할 필요가 있습니다.

권장 순서:

> 첫 자동화 대상은 반복이 많고 실패를 되돌릴 수 있는 업무다. 이 조건이면 샘플 자료로 빠르게 시험하고 오류 비용을 통제할 수 있다.

### 5.2 영어 사용 기준

영어는 고유명사, 실제 파일명, 실제 명령어, 현업 직함에만 사용한다. 개념 설명은 한국어를 우선한다.

| 영어·업계 표현 | 장표 기본 표현 | 사용 원칙 |
|---|---|---|
| AI Native | AI 중심 업무 | 영어 표현은 발표자 설명에서만 보조 |
| Harness engineering | 연구 환경 설계 | 첫 등장에는 `하네스 엔지니어링(연구 환경 설계)` 병기 가능 |
| Prompt engineering | 요청 설계 | 실제 요청문을 보여줄 때만 `프롬프트` 병기 |
| Agent | 도구를 사용하는 AI·AI 동료 | 제품명이나 기술 단계에서는 에이전트 허용 |
| Local | 내 컴퓨터 | 비전공자 설명에서는 반드시 한국어 사용 |
| API | AI 기능 연결·외부 기능 연결 | 실제 명령어나 개발 설명에서는 API 허용 |
| Preview | 웹 공유·임시 웹 주소 | Vercel 기능명 설명에서만 프리뷰 병기 |
| Pilot | 작은 현장 실험 | 사업 공식 명칭이 아니면 한국어 사용 |
| QA | 품질 점검 | 파일명·직무명 외에는 한국어 사용 |
| Governance | 책임·권한·관리 체계 | 의미에 맞춰 구체적으로 번역 |
| Claim | 주장 | 자료 구조의 실제 열 이름일 때만 영문 유지 |
| Evidence state | 검증 상태 | 확인 완료·초록만 확인·추가 확인·제외로 표현 |

### 5.3 피해야 할 표현

- `혁신적`, `획기적`, `압도적`, `완벽한`처럼 근거 없는 과장
- `AI가 알아서`, `완전 자동화`, `사람 없이`처럼 책임 구조를 지우는 표현
- `어디까지 가능한가요? 거의 다 가능합니다`처럼 범위를 모호하게 넓히는 표현
- `핵심 기반`, `인사이트를 제공`, `고도화를 도모`처럼 의미가 겹치거나 추상적인 표현
- 같은 절에서 `~합니다`, `~됩니다`, `~할 수 있습니다`가 연속되는 제목
- 불필요한 영문 대문자 제목과 슬래시 나열

### 5.4 권장 어휘

- 가능성보다 `적용 범위`
- 혁신보다 `업무 변화`
- 자동화보다 `입력·산출물·검증의 연결`
- 정확성보다 `근거 위치와 확인 상태`
- 사용자보다 `연구자·운영 담당자·콘텐츠 담당자`처럼 구체적인 사람
- 서비스보다 `운영 요약·콘텐츠 품질 점검·근거 지도`처럼 구체적인 화면

### 5.5 연구 전문성을 전제로 한 도구 설명

- 연구방법·정책·사업 관리 전문성을 이미 보유한 청중으로 설정한다.
- Codex 활용 경험의 차이를 연구 역량의 차이처럼 표현하지 않는다.
- 기능 설명보다 연구사업의 산출물·근거·검토·책임 구조를 먼저 제시한다.
- `여러분을 개발자로 만드는 시간`, `빈칸을 채우는 시험`, `막히면 하지 않아도 된다`, `누구나 쉽다`와 같은 표현을 사용하지 않는다.
- 영어는 고유명사와 실제 파일명에만 남기고, 낯선 기술 용어는 한 문장으로 정의한다.
- 실습 대안은 배려 문구가 아니라 실행 조건과 대체 절차로 명시한다.
- 부연 설명은 판단에 필요한 경우에만 사용하고 장표의 결론을 반복하지 않는다.

## 6. 강의 서사 구조

| 구간 | 장표 | 핵심 질문 | 청중이 얻어야 할 결론 |
|---|---:|---|---|
| 시작 | 1–5 | 왜 이 강의를 듣는가 | 코딩 강의가 아니라 연구 업무를 설명·검증하는 관점의 강의 |
| 첫 부탁 | 6–14 | 가장 먼저 어디에 써볼 것인가 | 자료를 사실·확인 필요·다음 행동으로 나누는 1쪽 정리 |
| 연구 환경 | 15–26 | 같은 일을 안심하고 다시 맡기려면 | 자료·순서·기준·실행·결과·변경의 여섯 약속 |
| 부탁의 구조 | 27–39 | 처음 쓰는 사람은 어떻게 말하면 되는가 | 평소 말로 시작하고 결과를 보며 한 가지씩 수정 |
| 화면으로 확인 | 40–59 | 어디까지 눈으로 확인할 수 있는가 | 학생지원 시안, 노트북, GitHub, 웹 공유의 연결 |
| 안전한 경계 | 60–67 | 무엇을 맡기고 언제 사람에게 물을 것인가 | 영향·복구 가능성·근거 수준에 따른 승인 |
| 작은 시작 | 68–71 | 강의 다음 날 무엇을 시작할 것인가 | 한 가지 부탁, 역할 분담, 90일의 다음 결정 |

각 구간은 `질문 → 기준 → 화면 → 적용`의 순서로 진행한다. 기술 설명이 먼저 나오지 않도록 KEDI 업무 사례를 앞에 둔다.

## 7. 장표 유형별 구성 기준

### 7.1 표지

- 제목, 부제, 강사 정보, 일정만 배치
- 블랙 배경과 흰색 제목으로 강한 시작
- 기술명을 나열하지 않고 강의가 다루는 변화 한 가지를 부제로 설명

### 7.2 강사 소개

- 소개 장표에서 표지의 강사 이름을 반복하지 않음
- `현재`, `이력`, `연락처`의 세 영역을 순서대로 사용
- 현재는 현업 `AI 서비스 기획·개발`과 부업 `AX·AI Native 강의·멘토링`으로 구분
- 이력은 직무 `개발자 → Agentic AI PM`, 산업 `금융 → 의료 → 교육 → 이커머스`, 기술 `ML → CV → LLM → Agent`만 압축해 표기
- LinkedIn, 이메일, 전화번호는 공개용 연락처만 사용
- AI 활용·업무 적용 문의가 가능하다는 안내는 한 문장 이내로 제한
- 발표자 사진이나 경력 로고를 과도하게 배치하지 않음

### 7.3 구분 장표

- 절 번호, 명사형 핵심 제목, 한 문장 설명
- 제목은 `업무 재설계`, `연구 환경 설계`, `요청 설계`, `실제 시연`, `안전한 활용`, `실행`처럼 다음 구간의 역할을 명확히 표현
- 본문 없이 전환 호흡을 만드는 용도

### 7.4 핵심 주장 장표

- 큰 문장 또는 공식 하나
- 보조 설명은 두 줄 이내
- 제목은 판단의 주제, 중앙 문장은 발표자가 강조할 결론

### 7.5 비교 장표

- 비교 축은 하나만 사용
- 좌우의 항목 수와 문장 길이를 맞춤
- `기존/개선`, `요청 설계/연구 환경 설계`, `후보/근거`처럼 비교 대상을 한국어로 명시

### 7.6 단계·절차 장표

- 3–5단계가 적정
- 각 단계 제목은 2–6어절
- 단계 설명은 두 줄 이내
- 화살표는 시간 순서나 승인 흐름이 있을 때만 사용

### 7.7 실제 화면 장표

- 화면 전체보다 발표자가 볼 지점을 확대
- 검은 설명 상자는 한 개만 사용
- 화면에 영어 코드가 많으면 제목과 설명 상자는 한국어로 해석
- 스크린샷을 장식으로 사용하지 않고 시연 실패 시 대체 자료로도 기능하게 구성

### 7.8 코드·자료 구조 장표

- 실행할 핵심 줄이나 입력·산출물 구조만 제시
- 교육 목적의 예시는 한국어 필드명을 우선
- 실제 파일명과 명령어는 원형 유지
- 코드가 작아지면 내용을 줄이고 전체 코드를 넣지 않음

### 7.9 위험·윤리 장표

- 추상적인 윤리 선언보다 승인 시점과 금지 범위를 제시
- 개인정보, 핵심 인용, 정책 결론, 학생 평가의 경계를 구분
- 낮은 위험·주의 필요·높은 위험의 세 단계 색상 유지

### 7.10 마무리 장표

- 새로운 내용을 추가하지 않음
- 사람이 방향을 정하고 AI가 실행하며 근거로 판단한다는 구조로 회수
- 참가자가 다음 날 시작할 업무 한 가지를 남기도록 안내

### 7.11 PRD·성과지표 장표

- PRD를 기능 요구사항 목록으로 표현하지 않고 `문제 → 작은 예상 → 하지 않을 일 → 확인할 변화` 순서로 구성
- `PRD`는 처음 한 번 `제품 기준 문서`로 풀어 설명하고, 문서 이름보다 네 칸의 합의를 강조
- 중심 지표만 강조하지 않고 결과·품질·안전 지표를 같은 위계로 배치
- 수치가 실제 성과인지, 파일럿 전 합의할 목표·통과 조건인지 화면에서 구분
- 기능마다 연결되는 사용자 문제와 지표를 발표자 노트에 남김
- 확대뿐 아니라 수정·축소·중단을 정상적인 다음 결정으로 표현

## 8. 시각 체계

### 8.1 기본 인상

- 블랙과 화이트 중심의 편집 디자인
- 무신사와 기술 발표 자료에서 느껴지는 간결한 대비
- 장식보다 정보 위계와 여백을 우선
- 둥근 카드가 반복되는 제품 화면형 디자인은 지양
- 민트·연두의 동시 사용을 배제하고, 코발트 블루 한 계열로 강조 위계를 통일

### 8.2 색상

| 용도 | 색상 | 값 |
|---|---|---|
| 기본 블랙 | 표지·구분·핵심 주장 | `#050505` |
| 기본 화이트 | 본문 배경·흰색 글자 | `#FFFFFF` |
| 웜 화이트 | 밝은 장표 배경 | `#F6F6F4` |
| 코발트 블루 | 핵심선·구조·주요 강조 | `#4F5FFF` |
| 라이트 인디고 | 어두운 장표의 절명·번호 | `#8E9AFF` |
| 블루그레이 | 보조선·절 전환·두 번째 위계 | `#9299AA` |
| 절제된 적갈색 | 위험·대비·주의가 필요한 경우 | `#C85D52` |

한 장표에서 강조색은 원칙적으로 한 가지, 비교 장표는 두 가지까지 사용한다. 초록·노랑·빨강은 위험 수준을 구분하는 표에서만 의미 색상으로 허용한다.

### 8.3 서체와 크기

- 기본 서체: 나눔고딕 또는 호환 가능한 한국어 고딕체
- 표지 제목: 50–58pt
- 구분 장표 제목: 40–46pt
- 일반 장표 제목: 34–40pt
- 중간 제목·열 제목: 22–28pt
- 본문: 16–20pt
- 출처·하단 정보: 11–13pt

글자가 많으면 크기를 줄이기보다 문장을 줄이거나 장표를 분리한다.

### 8.4 정렬과 여백

- 16:9 화면, 좌우 기본 여백 약 72px
- 제목·본문·하단선의 왼쪽 기준선 통일
- 열 사이 간격은 최소 24px
- 제목 아래 내용 시작 위치를 장표 유형별로 통일
- 페이지 번호와 절명은 하단에 작게 고정
- 한 장표 안에서 기준선은 세 개 이하로 제한

## 9. 이미지·유머·화면 자료 기준

- KEDI 공식 조직도, 정부·국제기구 문서, 실제 GitHub·Jupyter 화면을 우선 사용
- 로봇, 빛나는 뇌, 우주 배경 같은 일반적인 생성형 AI 이미지는 사용하지 않음
- 유머 이미지는 흐름을 끊지 않고 운영 비용·검증 필요성으로 바로 회수
- GIF는 발표 환경에서 재생이 불안정할 수 있으므로 핵심 정보 전달 용도로 사용하지 않음
- 외부 이미지는 장표와 발표자 노트에 출처·이용 조건을 기록
- 같은 이미지를 여러 장표에서 반복하지 않음

## 10. KEDI 맞춤화 기준

### 10.1 업무 언어

기술 기능보다 연구실의 업무 단위를 먼저 사용한다.

- 온라인학습 운영 요약
- 과정·콘텐츠 문의 유형 정리
- 교사 지원 요청 분류
- 온라인 콘텐츠 품질 점검
- 연구 근거 지도
- 인용 점검
- 시스템·콘텐츠·운영 개선 기록

### 10.2 사람 중심 설명

비전공 연구자에게 다음 네 문장을 반복적으로 제공한다.

1. 프로그램을 직접 만들지 않아도 원하는 도움을 평소 말로 설명할 수 있다.
2. 먼저 내 컴퓨터에서 가상 자료로 화면을 확인할 수 있다.
3. 필요한 경우에만 승인된 자료와 AI 기능을 연결할 수 있다.
4. 웹으로 공유하더라도 최종 판단과 공개 승인은 사람이 맡는다.

### 10.3 자동화 범위

가능하다는 이유만으로 자동화하지 않는다.

- 우선 적용: 공개 자료 수집, 파일 정리, 형식 변환, 후보 분류, 검토 목록 생성
- 사람 승인 필요: 원문 요약, 연구 코드 초안, 운영 요약, 콘텐츠 수정 제안
- 자동화 제외: 학생·교사 평가, 연구윤리 판단, 핵심 인용 확정, 정책 결론, 대외 발표 확정

### 10.4 현재 사업과 강의 제안의 구분

KEDI 공개 자료에서 확인되는 현재 사업·기능과 강의자가 제안하는 프로토타입을 같은 문장으로 섞지 않는다.

- `공개 자료로 확인`: 스쿨포유·하트포유 원격수업 콘텐츠의 2026년 AI 디지털 클론 활용
- `강의에서 제안`: 목표·작은 실행·사람 도움·회고를 연결하는 ‘이번 주 학습 길잡이’
- 공개 확인이 어려운 대화형 AI 서비스는 `현재 개발 중`으로 표현하지 않음
- 시안 하단에는 `강의 제안용 · 현재 운영 서비스가 아님`을 표시

### 10.5 학생지원 서비스의 제품 문서

학생 대상 서비스 장표는 다음 질문에 답해야 한다.

1. 어느 학생의 어떤 상황을 다루는가
2. 학생이 지금 해결하려는 일은 무엇인가
3. 이번 MVP에서 하지 않는 일은 무엇인가
4. 어떤 행동 변화와 안전 조건으로 성공을 판단하는가
5. 어떤 승인·동의·접근성 검토 후 현장 실험으로 넘어가는가

## 11. 실제 시연 구성

### 11.1 시연 1: 학생지원 MVP

`학생 문제 → 1쪽 PRD → 내 컴퓨터의 화면 시안 → 가상 자료 시험 → 사람 도움 연결 → 성과·안전 확인` 순서로 보여준다.

기술 이름을 먼저 설명하지 않고 “어디에서 무엇이 움직이는가”를 먼저 설명한다.

- 목표 선택과 활동 완료는 학생이 직접 조작
- 자신감이 낮으면 다음 행동의 크기를 줄이는 규칙 확인
- 도움 요청은 AI 답변이 아니라 담당자에게 보낼 문장 확인으로 마무리
- 자동 채점·위험 예측·건강 진단이 없음을 화면에서 확인
- AI API 없이도 핵심 가설을 먼저 검증할 수 있음을 설명

### 11.2 시연 2: Research-agent

연구질문, 검색, 점수화, 전달 자료, 원문 확인, 인용 점검이 파일로 연결되는 모습을 보여준다. 노트북 실행 성공보다 다음 산출물과 검증 기준을 강조한다.

### 11.3 Vercel 설명

Vercel은 완성 서비스가 아니라 동료에게 화면 시안을 보여주는 임시 웹 주소로 설명한다. 배포 자체를 성과로 제시하지 않고 사용성 의견을 받는 단계로 위치시킨다.

## 12. 근거·보안·책임 기준

- 외부 주장과 이미지의 출처는 발표자 노트 `[Sources]`에 기록
- DOI·저자·연도·페이지를 추정하지 않음
- 원문을 확인하지 않은 핵심 인용은 `초록만 확인` 또는 `추가 확인`으로 표시
- 실제 학생·교사·참여자 식별정보를 강의 시안에 입력하지 않음
- AI 연결용 비밀 키를 브라우저 코드와 PPT에 넣지 않음
- 원본 노트북과 원본 자료를 덮어쓰지 않음
- 자동 판단이 아니라 사람의 검토·승인 지점을 화면과 설명에 명시

- [ ] 웹 주소와 내 컴퓨터 시연 경로가 작동하는가

## 15. 이 강의 자료의 최종 톤앤매너

이 강의의 말투는 기술을 과시하는 전문가가 아니라 연구자의 업무를 함께 풀어보는 동료 전문가의 말투다.

- 전문적이되 어려운 단어를 앞세우지 않음
- 단정적이되 가능 범위와 확인 조건을 함께 제시
- 긍정적이되 자동화의 한계와 사람 책임을 생략하지 않음
- 형식적이되 보고서식 행정 문구로 흐르지 않음
