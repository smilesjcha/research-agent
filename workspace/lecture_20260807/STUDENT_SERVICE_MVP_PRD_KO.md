## 1. 공개 자료로 확인되는 현재 맥락

## 2. 함께 만들 수 있는 네 가지 MVP 후보

아래 점수는 사실 측정값이 아니라 강의 워크숍용 상대평가다. 1점은 낮음, 5점은 높음이며 안전성은 위험을 통제하기 쉬울수록 높은 점수다.

| 후보 | 학생이 얻는 도움 | 학생 가치 | 4주 내 검증 | 안전성 | 다른 사업 재사용 | 합계 |
|---|---|---:|---:|---:|---:|---:|
| 이번 주 학습 길잡이 | 목표·할 일·다음 행동·도움 요청·회고 | 5 | 5 | 4 | 5 | 19 |
| 쉬운 콘텐츠 동행 | 어려운 문장·용어·활동을 더 쉬운 표현으로 제시 | 4 | 4 | 4 | 4 | 16 |
| 사람 도움 연결 길잡이 | 질문 유형을 정리해 교사·운영자에게 전달 | 5 | 3 | 3 | 4 | 15 |
| 학생 목소리 요약 | 비식별 만족·불편 의견을 주제별로 묶어 개선안 도출 | 3 | 5 | 5 | 3 | 16 |

추천 순서는 **이번 주 학습 길잡이 → 쉬운 콘텐츠 동행 → 사람 도움 연결 길잡이**다. 첫 후보는 자동 채점이나 학생 예측 없이도 학생이 바로 체감할 수 있고, 가상 자료만으로 전체 흐름을 먼저 시험할 수 있다.

## 3. 1쪽 PRD

### 제품 한 문장

온라인 학습자가 매주 해야 할 일을 작은 행동으로 나누고, 막힐 때 사람에게 도움을 요청하며, 학습을 한 문장으로 돌아보게 하는 학생지원 화면.

### 해결할 문제

온라인 학습에서는 해야 할 일, 진도, 질문 경로가 여러 화면과 안내에 흩어질 수 있다. 학생은 “지금 무엇부터 해야 하는지”, “막혔을 때 누구에게 어떻게 질문할지”를 판단하는 데 추가 부담을 느낄 수 있다.

이 문장은 서비스 가설이다. 실제 학생 인터뷰와 이용 행태 자료로 문제의 빈도·심각도·대상을 먼저 확인해야 한다.

### 주요 사용자와 해야 할 일

- 1차 사용자: 온라인 보충과정 등 온라인으로 과목을 이수하는 학생
- 사용자가 해결하려는 일: “이번 주 학습에서 지금 할 수 있는 다음 행동을 알고, 막히면 부담 없이 사람에게 도움을 요청하고 싶다.”
- 보조 사용자: 학습지원 담당자·교사·사업 운영자
- 보조 사용자의 일: “학생이 보낸 질문을 맥락과 함께 받고, 지원이 해결되었는지 확인하고 싶다.”

### 가치 가설

해야 할 일을 작은 단위로 보여주고 사람 도움 요청을 한 화면에 연결하면, 학생이 계획–실행–회고 순환을 더 자주 완주하고 필요한 지원을 더 빨리 받을 수 있다.

### 핵심 기능: 반드시 필요한 것

1. 이번 주 목표 한 가지 선택
2. 학습 활동을 5~20분 단위로 제시
3. 규칙 기반 ‘다음 한 걸음’ 안내
4. 시작 자신감에 따른 활동 크기 조정
5. 사람이 받는 도움 요청 문장 만들기
6. 한 문장 회고와 주간 진행 표시
7. 자동 평가·자동 조치가 없다는 안내

### 이번 MVP에서 하지 않는 것

- 자동 채점, 등급, 순위, 학업 성취 판단
- ‘위험 학생’ 예측·낙인·불이익 조치
- 건강·심리 상태 진단이나 상담
- 공개형 생성 AI에 실제 학생 정보 전송
- 사람 확인 없는 알림·지원 배정·기록 반영
- 여러 KEDI 사업을 하나의 동일 규칙으로 통합

### 이후 검토할 기능

- 승인된 학습관리시스템과 과제 목록 연동
- 교사가 확인한 쉬운 설명·대체 형식 콘텐츠
- 접근성 설정과 보조기기 호환
- 운영 담당자의 비식별 집계 화면
- 기관 승인 환경의 AI 보조 문장 생성

## 4. 사용자 흐름

```text
이번 주 목표 선택
  → 오늘 할 일을 작은 단위로 확인
  → 시작 자신감 표시
  → 다음 한 걸음 실행
  → 막히면 사람에게 도움 요청
  → 해결 여부 확인
  → 한 문장 회고
  → 다음 주 계획 조정
```

핵심은 추천 정확도보다 **학생이 다음 행동을 이해하고 필요할 때 사람에게 연결되는지**다.

## 5. 성공 지표

### 중심 지표

**주간 계획–실행–회고 완주율**

- 분자: 7일 안에 목표 선택, 학습 활동 1개 이상 완료, 한 문장 회고를 모두 수행한 참여자 수
- 분모: 해당 주에 1개 이상의 학습 활동이 배정되고 파일럿 참여에 동의한 사용자 수
- 해석: 성적이나 능력 지표가 아니라 서비스가 자기조절 학습 순환을 지원했는지 보는 사용 지표

### 결과 지표

- 배정된 핵심 활동 완료율의 파일럿 전후 변화
- 학생이 느끼는 ‘다음 할 일의 명확성’
- 도움 요청 해결률과 해결까지 걸린 시간
- 학생·교사의 지속 사용 의향

### 선행 지표

- 첫 목표 설정률
- 첫 방문 후 7일 내 재방문율
- 다음 행동 안내 확인률
- 도움 요청 문장 작성률과 실제 전달 전 취소율

### 품질 지표

- 학생이 추천 문장을 이해한 비율
- 담당자가 본 질문 맥락의 충분성
- 접근성 점검에서 발견된 중대 문제 수
- 규칙별 잘못된 다음 행동 제시율

### 안전 지표와 초기 통과 조건 제안

- 자동 평가·자동 불이익 조치: 0건
- 가상 자료 단계의 실제 식별·민감정보 입력: 0건
- 모든 도움 요청 시나리오에서 사람 연결 경로 노출: 100%
- 중대한 접근성 오류: 0건 이후 학생 파일럿 진입
- 잘못된 추천은 원인을 기록하고 수정 전 해당 규칙 중단

수치 기준은 확정 성과가 아니라 파일럿 시작 전 팀이 합의할 **의사결정 기준 초안**이다.

## 6. 검증 계획

### 0단계: 가상 자료와 내부 검토

- 대상: 연구·운영 담당자 5명 내외
- 자료: 가상 과제, 가상 진행 상태, 가상 도움 요청
- 과업: 목표 선택부터 회고까지 실행하며 혼란·오류·위험 문구 표시
- 통과 조건: 핵심 과업 완료, 중대 접근성 문제 0건, 자동 판단 없음 확인

### 1단계: 문제 인터뷰

- 대상: 기관 승인과 동의 절차를 거친 목표 사용자·교사
- 질문: 이번 주 해야 할 일을 찾는 과정, 시작을 미룬 이유, 도움 요청 경험, 기존 해결 방법
- 산출물: 문제 빈도·심각도·현재 대안·대상별 차이
- 중단 조건: 핵심 문제가 드물거나 기존 기능으로 충분히 해결되는 경우

### 2단계: 제한된 사용성 실험

- 권장 규모: 10~15명 수준의 탐색적 시험 후 별도 표본설계
- 기간: 2~4주
- 비교: 기존 안내 흐름과 MVP 사용 흐름의 시간·오류·완주 경험
- 해석: 통계적 효과 확정이 아니라 다음 실험 가치와 위험을 판단

### 3단계: 효과 연구

- 연구질문·표본수·분석계획·윤리·동의 절차를 사전 확정
- 자기조절학습, 학습 지속, 도움 요청과 같은 구성개념은 검증된 측정도구와 원문 근거 확인 후 사용
- 사업별 학생 특성을 하나로 합치지 않고 하위집단별 접근성과 형평성 검토

## 7. 현대적인 제품·연구 운영 방식

### 하나의 기준 문서

PRD는 기능 목록이 아니라 문제·근거·성과·비범위·위험·실험을 연결하는 기준 문서다. GitHub에서 변경 제안과 검토 이유를 함께 남긴다.

```text
product/
├── 00_problem.md          # 사용자 문제와 근거
├── 01_prd.md              # 가치·비범위·핵심 기능
├── metrics.yaml           # 지표 정의와 분모·분자
├── experiments/           # 가설·방법·결과·다음 결정
├── decisions/             # 채택·보류·중단 이유
├── prototype/             # 작동 시안
└── tests/                 # 기능·접근성·안전 점검
```

### 기능보다 성과를 먼저 쓰는 순서

1. 문제 정의: 누구의 어떤 어려움인가
2. 근거 상태: 공개 자료, 인터뷰, 행태 자료 중 무엇을 확인했는가
3. 결과 가설: 어떤 변화가 생기면 가치가 있는가
4. 성공·안전 지표: 무엇을 어떻게 측정할 것인가
5. 비범위: 무엇을 하지 않을 것인가
6. 핵심 기능: 가설 검증에 꼭 필요한 최소 기능은 무엇인가
7. 실험: 누구에게 얼마나 작게 시험할 것인가
8. 결정: 확대·수정·중단 중 무엇을 선택했으며 이유는 무엇인가

### GitHub 변경 검토 질문

- 이 기능이 연결되는 사용자 문제와 지표는 무엇인가?
- 새로 수집하는 데이터가 정말 필요한가?
- 학생에게 미치는 영향과 되돌리는 방법은 무엇인가?
- 자동화되지 말아야 할 판단은 무엇인가?
- 실험 실패 시 무엇을 배우고 어떤 기능을 제거할 것인가?

## 8. 90일 실행안

### 1~30일: 문제와 기준

- 공개 업무·기존 화면·문의 유형 검토
- 연구자·교사·학생 인터뷰 계획과 승인
- 문제 정의, 비범위, 지표 사전 합의
- 가상 자료 기반 로컬 MVP 제작

### 31~60일: 사용성과 안전

- 내부 5명 과업 시험
- 접근성·문구·도움 요청 경로 수정
- 데이터 최소화·권한·로그·중단 절차 검토
- 학생 파일럿 진행 여부 결정

### 61~90일: 제한된 파일럿과 다음 결정

- 승인된 대상에게 2~4주 사용성 실험
- 결과·품질·안전 지표 함께 확인
- 사업 확대, 대상별 재설계, 기능 축소, 중단 중 하나를 결정
- PRD·결정 기록·다음 실험안을 GitHub에 갱신

## 9. 장기 방향

장기 목표는 ‘AI 기능이 많은 서비스’가 아니라, 학생이 자신의 학습을 이해하고 선택하며 필요할 때 사람에게 연결되는 지원 환경이다. AI는 승인된 자료 안에서 쉬운 설명, 질문 문장, 회고 초안을 보조할 수 있지만 학생을 평가하거나 지원 자격을 결정하는 주체가 되어서는 안 된다.

서비스 개선은 다음 순환을 반복한다.

```text
학생 문제 발견 → PRD와 비범위 합의 → 로컬 시안 → 작은 실험
→ 결과·품질·안전 확인 → 확대·수정·중단 결정 → 다음 PRD
```
